## 4. Product definition

**Input event kinds:** `message`, `image`, `audio`, `call_event` (plus a `draft: true` flag for the pre-send nudge).

**Response fields:** `severity` (0–100), `tier` (`low` 0–30, `review` 31–60, `high` 61–85, `urgent` 86–100), `reasons[]`, `signals{}` (per module: text, ocr, image, audio, call, behavior, pile_on, pii), `recommended_action` (`log`, `warn_sender`, `blur_media`, `throttle`, `escalate`), plus optional secondary actions.

**Tier triggers and actions (configurable in `config/fusion.toml`):**

| Tier | Example triggers | Action |
|---|---|---|
| Low (0–30) | Isolated mild toxicity | Log; optional sender nudge |
| Review (31–60) | Rising persistence, repeated unreplied messages or calls | Queue for moderator; soft warning to sender |
| High (61–85) | Contact after block, escalating threats, unsolicited explicit media | Auto-blur/hide, throttle sender, alert moderator |
| Urgent (86–100) | Explicit threats, sextortion, grooming patterns, NCII/deepfake of a real person | Immediate human review, restrict account, victim-support and reporting guidance |

**What the engine does NOT do (state it in docs and the pitch):** read private DMs elsewhere without cooperation; tap live phone calls; link one person's accounts across platforms; reliably detect grooming, new-generator deepfakes, or cloned voices; understand sarcasm perfectly; judge intent from tone alone; replace human moderators.

### 5.2 Request flow

`validate → pseudonymize ids → idempotency check (event_id) → persist event (skip if draft) → run modality pipelines concurrently (tokio::join!, inference in spawn_blocking) → load behavior features from store → fusion → persist alert if tier ≥ review → publish SSE → return response`.

Media: image goes through NSFW + pHash + (OCR → text pipeline + PII) + face/deepfake; audio goes through decode → Whisper → text pipeline → tone (supporting only). Long audio (voicemail) is processed asynchronously: respond `202` with a job id and push the result by SSE and `GET /v1/jobs/{id}`; short voice notes (<15 s) process synchronously.

### 5.3 Performance budgets (CPU laptop, enforce with benches and a `/v1/metrics/latency` endpoint)

| Path | p95 target | How |
|---|---|---|
| Text, fast tier | ≤ 80 ms | quantized small model, warm sessions, `intra_threads` configured |
| Text escalation (ambiguous scores 0.35–0.75) | ≤ 400 ms | run the accurate large model only when the fast score is ambiguous |
| Image | ≤ 400 ms | tiny ViT NSFW at 384px, pHash, OCR only if image has text-like regions or on request |
| Audio ≤ 15 s | ≤ 4 s | Whisper base int8/ggml; `small` optional |
| Behavior + fusion | ≤ 10 ms | pre-aggregated window queries, indices on `(pair_key, occurred_at)` |

Also: warm up all sessions at startup, bounded concurrency per modality (semaphores), per-request deadline with partial results (`degraded: ["image.timeout"]`), content-hash cache for repeated text/images.

Slang confirm/reject, alert review, model reload, and demo-reset require moderator/admin. Errors are RFC 7807 `application/problem+json`. Rate limit and body-size limits enabled (image ≤ 10 MB, audio ≤ 25 MB).

```json
  "recipient_id": "opaque string (post owner / target for comments)",
```


## 9. Behavior module (centerpiece)

**9.1 Message-pair features** (windows `1h`, `24h`, `7d`; computed per directional pair; the single source of truth is `docs/FEATURES.md` with names, formulas, units, and order, and a **golden-vector test** so Rust reproduces Python's features within 1e-4):

`msg_count_{w}`, `unreplied_streak`, `reply_ratio_{w}`, `initiator_ratio`, `median_gap_s`, `burst_max_10m`, `night_ratio_{w}` (recipient local time, configurable), `after_refusal_count`, `since_refusal_hours`, `active_days_streak`, `tox_mean_{w}`, `tox_max_{w}`, `threat_max_{w}`, `sexual_max_{w}`, `tox_slope_last20` (OLS), `sent_mean_{w}`, `sent_slope_last20`, `pii_mentions_{w}`, `location_cue_count_{w}` ("I saw you at", "outside your", "I know where…" patterns), `unsolicited_media_count_{w}`, `repetition_score` (mean pairwise similarity), `sender_account_age_days`, `is_contact`, `distinct_channels`, `evasion_similarity`.

**9.2 Call features** (`hre-calls`): `call_count_{w}`, `max_calls_1h`, `unanswered_ratio_{w}`, `silent_calls_{w}` (answered, duration < 5 s), `avg_duration_s`, `night_call_ratio_{w}`, `after_block_calls`, `new_number_flag`, `gap_regularity` (std/mean of gaps), `voicemail_count_{w}`.

**9.3 Model + fallback:** `behavior_msg.onnx` and `behavior_call.onnx` (XGBoost→ONNX; `features.json` lists order; manifest stores the benign baseline vector). Fallback: weighted logistic over normalized features from `config/behavior_rules.toml`.

**9.4 Attribution (SHAP-like, in Rust):** for each feature, replace it with the benign baseline value, re-run the (tiny) model, and take the probability delta as its contribution. Top-k contributors become reasons via templates ("58 messages in 3 h, no replies", "14 calls in 2 h, all unanswered"). Name it "occlusion attribution" in docs; offline SHAP plots come from `training/`.

**9.5 Pile-on:** distinct senders per target per window, spike vs EWMA baseline, near-duplicate content, young accounts; output `pile_on` signal and `feed-protection` state (collapse replies, rate-limit).

**9.6 Benign heavy users (C4):** the model and rules must treat high reciprocity, long answered calls, and recipient-initiated contact as protective. Scenario 7 must stay in Low.

## 10. Fusion (`hre-fusion`)

1. Inputs: signals `text, ocr, image, audio, call, behavior, pile_on, pii` each in 0–1 with weights in `config/fusion.toml`.
2. Base score: noisy-OR `1 − Π(1 − wᵢ·sᵢ)` scaled to 0–100.
3. **Floors** (minimum severity): threat ≥ 0.9 → 86; sextortion pattern → 86; NCII hash match → 86; deepfake+NSFW composite → 86 (low-confidence flag); unsolicited explicit media from non-contact → 61 + `blur_media`; contact after block → 61 (≥ 3 attempts → 75); doxxing with toxicity → 70 (address+threat → 86).
4. **Caps/discounts:** reciprocal healthy conversation (reply_ratio > 0.4, recipient-initiated, no refusal) caps at 55 unless threat > 0.8; quoted-abuse and banter discounts; tone adds ≤ +10 and never flags alone.
5. Optional isotonic calibration table `calibration.json`.
6. Tier by thresholds; action by tier and conditions (`log` / `warn_sender` / `blur_media` / `throttle` / `escalate`, plus secondary actions).
7. Reasons: ordered, plain language, each with code, weight, evidence. Every floor/cap that fired appears as a reason.
8. Unit tests per floor/cap and one test per demo scenario tier.

## 11. Slang adaptation loop (`hre-slang`, F10 / Deliverable 3 / 1.8)

- **Normalizer:** leetspeak, spacing, homoglyphs, repeated chars, emoji→token.
- **Lexicon:** SQLite table (term, meaning, severity, language, added_by, ts, version); matched with `aho-corasick`; contributes a boost to the text signal, never alone above `review`.
- **Candidate miner (background task):** scans recent messages from risky conversations (behavior ≥ review, reported, or high toxicity) for tokens/bigrams that are out-of-vocabulary or rare; embeds them; keeps those close (cosine ≥ τ) to confirmed abusive anchors and seen from ≥ k distinct senders; queue with PII-masked example contexts.
- **Moderator gate:** `confirm` (with meaning + severity) / `reject`; moderator role only; every change audit-logged; **no auto-updates**.
- **Adapter head:** logistic regression on sentence embeddings, trained in Rust (`linfa-logistic` or a small hand-rolled SGD) from confirmed contexts + moderator-labelled flagged/rejected messages + a replay set of hard examples; versioned `adapter_head_vN.json`; scheduled (interval in config) and via `POST /v1/slang/retrain`. **Drift guard:** reject a new version if precision on the frozen validation set drops by more than 2 points; `rollback` endpoint.
- **Temporal-split experiment** (in `hre-eval`): hold out a set of invented code words, show misses before confirmation and detection after, with a before/after table. Use **invented** terms (e.g. "vexling") so no real slurs are needed.

## 12. Evidence (`hre-evidence`, F12/F17, deliverable 4)

- Timeline for a subject over `[from,to]`: messages, images (hash + scores + OCR text, never pixels), audio (transcript + scores), calls.
- Each record: id, UTC + local timestamp, platform, pseudonymous ids (plus optional victim-supplied labels at export time), scores, reasons, `sha256(canonical JSON)`, `prev_hash` (hash chain); manifest hash; HMAC signature of the export with a server key for tamper detection.
- Formats: canonical JSON, printable HTML (print CSS), PDF (stretch; `genpdf`/`printpdf`).
- `certificate_draft` section: lists source device/platform, timestamps, and hash values as an aid for the Indian electronic-evidence certificate (Bharatiya Sakshya Adhiniyam 2023, Section 63(4): Part A needs the hash value; Part B needs expert certification). Label it "draft aid, not legal advice; Part B must come from an expert; verify with counsel". Never call the export "court-certified".
- Footer resources (verify before demo): cybercrime.gov.in (anonymous reporting available for crimes against women and children), helpline 1930, women's helpline 181, emergency 112, StopNCII.org for intimate-image abuse.

## 14. Evaluation and test data (`hre-eval`, F13, deliverable 5)

**Metrics:** precision, recall, F1, false-positive rate, confusion matrix, PR curves per module (text, OCR, image, audio, call, behavior) and end to end; **detection rate** = share of harassment conversations flagged (≥ review); **time-to-detection** = events (messages or calls) until first ≥ review; keyword-baseline vs system on polite-stalker cases; ablation (text-only → + behavior → + calls → full); benign heavy-user FPR (messages and calls); OCR accuracy (CER/WER, reported separately); ASR WER on TTS audio; inter-annotator agreement (Cohen's κ script for two label files); slang temporal-split table; latency percentiles.

**Rules against circularity:** training uses synthetic **generator A** (`training/`, Python); evaluation uses **generator B** (Rust, different parameter ranges and structure) plus hand-written edge cases; all reports state that behavior results are on synthetic data. Build part of the text test set from fresh hand-written examples (leakage rule). Never collect real explicit/abusive imagery: use benign proxies, blurred placeholders, rendered-text screenshots, and TTS/acted audio (RAVDESS/CREMA-D for tone), all labelled synthetic.

**Scenario classes for generators:** normal, heavy_benign (couple, friends, fandom, family), polite_stalker, escalating_stalker, post_block_contacter, pile_on, bully, cyberflasher, sextortion, silent_caller, night_caller, post_block_caller, new_number_caller, plus noisy/ambiguous cases.

**Test data plan:** text from Jigsaw, HateXplain, Davidson, TextDetox plus fresh hand-written examples; Hinglish/Hindi sample set; one Marathi/Konkani-like sample reported explicitly; call logs and message logs from generators; images (benign proxies, public benchmark samples handled carefully, self-made screenshots with rendered text); audio (TTS from public text, acted emotional speech).
